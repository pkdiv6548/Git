Getting started

This repository currently provides a static frontend prototype. Open index.html in a browser or serve this folder locally. No account service, repository storage or backend API is connected.

git clone https://github.com/pkdiv6548/Git.git
cd Git
python -m http.server 8000

Open localhost port 8000 in your browser.

Architecture target

Frontend: React + TypeScript + Vite with explicit routes and shared design tokens. Backend: Node.js + TypeScript + Fastify. PostgreSQL stores application metadata; a separate Git storage layer stores repositories and Git objects.

  • Keep Git objects and refs authoritative in Git storage.
  • Keep users, memberships, issues, reviews and notifications in PostgreSQL.
  • Version APIs under /api/v1 with request schemas and standard errors.
  • Keep secrets server-side and isolate background jobs and CI runners.

Git operations

The product must support actual Git clients, not only a simulated code browser. MVP operations include clone, fetch, push, branches, tags, commits, diffs and branch protection. HTTPS Smart HTTP and SSH need explicit authentication, authorization and transport implementation.

Do not advertise clone, push, merge or persistence as working until tested with real Git CLI clients against a running backend.

Security model

  • Authorize every request and Git operation on the server.
  • Do not leak private repository metadata through search, logs or errors.
  • Use secure sessions, password hashing, rate limits, input validation and secret redaction.
  • Constrain Git execution and isolate future CI jobs.
  • Test backup restoration and access-control boundaries.

Implementation roadmap

  1. Frontend routes and reusable design system.
  2. Database migrations, authentication, sessions, permissions and API contracts.
  3. Real Git repository storage, clone/fetch/push and code browsing.
  4. Issues, pull requests, reviews, organizations and notifications.
  5. Security hardening, automated tests, monitoring and backup/restore.
  6. Advanced CI/CD, Git LFS, SSH, packages and code scanning.

Current status

Frontend prototype. Navigation, theme switching, sample repository filtering and local form validation are implemented. Authentication, persistence, real Git transport, billing, CI/CD and backend-powered collaboration are not implemented.

A requirement is only Verified when a repeatable test passes and evidence is recorded. A UI screen alone does not prove the backend feature works.
